# Stage 10 — Discussion, critique and submission
Goal: draft Introduction, Discussion and Abstract from verified claim-support rows only, put them through an adversarial critique, and complete a disclosure that matches the target journal's live AI policy.

## Entry modes
- Runs normally in every mode once stage 09 is `PASSED`. The guard hook blocks draft/ until stage 09 sets `live_file: draft/`.
- `RETRO-AUDIT` in `c-half-draft` and `d-finished-manuscript`, and for the as-submitted text in `e-under-revision`. The existing Introduction and Discussion are committed into draft/ as the dated baseline and audited rather than drafted:
  - every citation must map to a `SUPPORT-CHECKED` CL row;
  - hypotheses first dated after a result are relabelled post hoc;
  - orphan claims are flagged [F1, F23, F28].
- Modes b–e: the Discussion gets a transparent post hoc subsection; the paper says "not preregistered" and never uses "registered" in a way that implies equivalence; exploratory findings are worded as preliminary [F1, F4 UNVERIFIED, F16].
- `e-under-revision`: the stage 09 retraction re-check of every cited R row must postdate the `submitted-<slug>-v<n>` baseline tag. The response letter, which is the user's file outside the chain, must use the same labels as question-map.md [F23, F29].
- `NOT-PASSABLE` when neither Claude nor the user can read the target journal's live AI policy before submission. Queue this disclosure item (one STATE.md line, ID + ≤6 words; full text in disclosure.md): "The journal AI policy could not be read on <date>; the disclosure follows COPE/ICMJE defaults" [D31, D32].

## Inputs / Live files / Outputs
- **Inputs:**
  - STATE.md, for the disclosure-queue lines and the prior-exposure statement; disclosure.md, for the queued items' full text;
  - intake.md, for the target journal;
  - doi-ledger.md as a grep-extracted slice only: the CL rows named in the skeleton copy or the question map, their R rows, and the layer-synthesis lines. No agent reads the whole ledger;
  - question-map.md, methods.md, results.md, analysis-log.md and templates/section-skeleton.md;
  - in modes c–e, the existing text pointed to by intake.md.
- **Live files:** first `live_file: draft/`, then `critique.md`, then `disclosure.md`. Step 5 switches briefly to `methods.md, results.md` for the citation fill, and fix rounds switch to the file being fixed.
- **Outputs:**
  - **draft/intro.md, draft/discussion.md, draft/abstract.md:** header `derives-from: doi-ledger.md@<short-commit>`. Skeleton bullets first, each with `[ledger: CL12, CL15]` or `[log: A03]`, then prose. They cite only `SUPPORT-CHECKED` CL rows.
  - **draft/references.md:** header `derives-from: doi-ledger.md@<short-commit>`; generated by the main session from the R rows of the cited CL rows, each `METADATA-OK`; never typed.
  - **critique.md:** the critic appends a `## Stage 10` section (stage 04 wrote `## Stage 04`); every item ends `resolved: <commit>` or `logged: <reason>`.
  - **disclosure.md** (main session; created here in mode a): target journal, policy URL, date read and the quoted policy line; the AI-use statement (tools with versions, purpose, human oversight, placement); every queued disclosure item; the references-checked declaration [D17]; a pointer to data and code availability.

## Model and agent
- **agents/drafter.md:** Opus 5.5 (`claude-opus-5-5`), `effort: medium` in its frontmatter, one section per run, md only, ≤60k input tokens. It never writes disclosure.md.
- **agents/critic.md:** Opus 5.5 at effort high, run as a fresh subagent that saw none of the drafting turns. It must find errors, and its output is ≤120 lines.
  - It appends its section to critique.md itself and returns a ≤10-line summary; it never edits the drafts [A24, A25].
- **Main session (Opus 5.5):** sets the live files; extracts the ledger slices; runs the citation-map and number checks; generates draft/references.md; re-reads the policy and writes disclosure.md.
  - It may call agents/source-rechecker.md (Sonnet 5.5, ≤20k tokens) when the critic disputes a passage.
- **Escalation to Fable 5.1:** prose polish only, after Opus 5.5 fails an acceptance check in the critique round; in a new session, because switching model mid-session re-reads the history uncached; check retention terms first [A5; A19 C UNVERIFIED; E6].
  - Fable never touches numbers, labels or citations, and its use is recorded in disclosure.md.

## Procedure
1. Read STATE.md and stop unless stage 09 is `PASSED` and `live_file: draft/`, committing the existing text into draft/ first as the baseline in modes c–e.
2. The main session fills a skeleton copy with the CL IDs of the to-be-cited list and passes it with the ledger slice; the drafter writes draft/intro.md, keeping each hypothesis's `origin:` tag and never presenting literature consulted after results as its a priori basis [C2].
3. The drafter writes draft/discussion.md per question in question-map order, nulls included, with the post hoc subsection and the "not preregistered" wording in modes b–e.
4. The drafter writes draft/abstract.md last, taking every number from results.md with its `[log: A<nn>]` pointer and keeping each finding's label.
5. The main session sets `live_file: methods.md, results.md`, replaces each `[GAP: cite — …]` with its `[ledger: CL<nn>]` (a pointer fill, no stale flag), sets `live_file: draft/` again, maps every cited CL ID to a `SUPPORT-CHECKED` row whose R row is `METADATA-OK`, and generates draft/references.md. A newly needed source goes to inbox.md for stages 08–09 and stays uncited until then.
6. Set `live_file: critique.md` and run the critic as a fresh subagent on the section files, question-map.md, analysis-log.md and a ledger slice of the cited CL rows and their R rows. It reports errors (overclaiming, unlabelled post hoc results, number mismatches, unverified citations, missing nulls, disclosure gaps) under `## Stage 10`.
7. Resolve each critique item in the live file it concerns, switching live_file or going through inbox and propagate, and mark it `resolved: <commit>` or `logged: <reason>` in critique.md.
8. Set `live_file: disclosure.md`, re-read the target journal's live AI policy (WebFetch, or a copy the user pastes), record URL, date and the quoted line, and complete disclosure.md with every queued item [D27–D32]. Check that the methods.md AI-use statement says the same.
9. In mode e, confirm the stage 09 retraction re-check postdates the baseline tag, and compare the response letter's labels with question-map.md.
10. Export the full draft for the advisors, run the gate, write STATE.md, commit, run `/rename <slug>-S10`, then `/clear`.

## Gate (pass/fail)
Run gate commands from paper-workflow/ (the project root for Claude Code).
- [ ] The stage 09 gate commit precedes the first draft/ commit: `git merge-base --is-ancestor <stage-09 commit> $(git log --format=%h -- papers/<slug>/draft/ | tail -1)`.
- [ ] Every draft/*.md has a `derives-from:` header, and `grep -h '^- ' papers/<slug>/draft/{intro,discussion,abstract}.md | grep -vcE '\[ledger: CL|\[log: A'` prints 0.
- [ ] `grep -c '\[GAP' papers/<slug>/draft/*.md papers/<slug>/methods.md papers/<slug>/results.md` prints 0 for every file.
- [ ] Citation map: every ID from `grep -oh '\[ledger: CL[^]]*\]' papers/<slug>/draft/*.md papers/<slug>/methods.md papers/<slug>/results.md | grep -o 'CL[0-9]*' | sort -u` is `SUPPORT-CHECKED`, with 0 `NOT-CITABLE`, 0 `RETRACTED` and 0 unknown IDs.
- [ ] draft/references.md lists exactly the R rows of the cited CL rows, each `METADATA-OK`.
- [ ] Every number in the Abstract and Discussion carries `[log: A<nn>]` and matches results/A<nn>.md.
- [ ] critique.md's `## Stage 10` section comes from a fresh critic subagent, has at least one item, and every item is `resolved:` or `logged:`.
- [ ] Modes b–e: the post hoc subsection is present, and "not preregistered" is present. A grep for "registered" finds no wording that implies equivalence with preregistration.
- [ ] disclosure.md has the policy URL, read date and quoted line, and every queued disclosure item, checked by count match against STATE.md.
- [ ] Its AI statement names every tool actually used (Claude models, NotebookLM, Fable if used) and sits where the policy requires.
- [ ] disclosure.md has the references-checked declaration.
- [ ] Mode e: the retraction re-check postdates the baseline tag, and the response letter's labels match question-map.md.
- [ ] The advisor export path and date are recorded.
- [ ] STATE.md updated: gate status, live_file for next stage, stale flags, open inbox count. Next: `live_file: intake.md`. When reviews arrive, re-enter at stage 00 in `e-under-revision` through its "existing paper" branch (STATE.md, inbox.md and data-access.md kept; baseline tag `submitted-<slug>-v<n>`).

## Propagate step
This runs at this gate, or when the user types "propagate inbox".
1. Read the OPEN inbox.md items that target draft/, critique.md, disclosure.md or upstream files.
2. Set `mode: propagate` and list the changes in plan mode.
3. Get user approval.
4. Edit upstream first: results.md before the Discussion. A new or changed citation re-runs stages 08–09 for that row.
5. Mark the affected draft files `stale:`.
6. Close each item as `CLOSED -> <file>@<commit>`, plus its critique item if it came from the critique. Then set `mode: work`.

## Advisor touchpoint (entry 3)
- **When:** after the critique round only, so that advisors see a draft that has already been attacked.
- **Export:** `cd papers/<slug> && pandoc draft/abstract.md draft/intro.md methods.md results.md draft/discussion.md draft/references.md disclosure.md -o draft-<date>.docx`, or `.pdf`. Attach question-map.md and the list of `logged:` critique items.
- **What the advisors are asked:**
  1. Does any sentence claim more than its question-map status, such as a null worded as a trend or an exploratory result worded as a test?
  2. Is every post hoc result in the post hoc subsection and worded as preliminary?
  3. Please spot-check two or three regional, national or local citations against their ledger quotes.
  4. Are the logged, unresolved critique items acceptable?
  5. Is the AI-use statement accurate for every author's use, and is the target journal right?
- Each reply point becomes one dated inbox.md line. Nothing is edited until the propagate step.
