## Compaction safety recipe
- Keep the protocol and gate rules in project-root CLAUDE.md (under 200 lines) or unscoped rules, never only in conversation or `paths:` rules (28, 32).
- Write stage state to a file on disk (e.g. STATE.md) and re-inject it with a SessionStart `compact` hook; hook output from before compaction is summarized, not kept (22, 32).
- Do bulk reading and verification in subagents or workflow scripts so intermediate output never enters the main window (5, 6, 14).
- Run `/compact focus on <stage>` at stage boundaries and add a "Compact Instructions" section to CLAUDE.md; lower the window with `/autocompact` if needed (30, 31).
- Put the most important instructions at the top of each SKILL.md, because skills are truncated at 5,000 tokens and the oldest are dropped past 25,000 total (11).
- Enforce gates from disk state with Stop/PreToolUse hooks, not from Claude's memory of the conversation; PreCompact exit 2 can block a compaction at a bad moment (20, 21).

## Implications for the workflow structure
- One `.claude/agents/<role>.md` per stage role with an explicit `model:`; because a per-invocation `model` outranks frontmatter (claim 4), set `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` or forbid the orchestrator from passing a model if strict pinning matters, and prefer full model IDs for reproducibility.
- Make stage boundaries file-based (artifact plus gate-status file) and gate with Stop/PreToolUse hooks; workflows cannot pause for sign-off, so use one workflow or skill per stage with the human gate between them (claims 16, 20).
- Keep the main session thin: CLAUDE.md under 200 lines with `@` imports, heavy work in subagents or workflow scripts, auto memory only for soft preferences (claims 5, 14, 28, 29).
- Treat redesigned Projects and Claude Docs as optional beta surfaces: Projects is cloud-thread based and Pro/Max only; Docs comments need Editor access and Docs has no version history, so keep the canonical manuscript in git and export from Docs (claims 34, 36).
- Use mods only for optional display (new in v2.1.287, unsandboxed); put deterministic enforcement in ordinary settings hooks (claims 23, 24).
